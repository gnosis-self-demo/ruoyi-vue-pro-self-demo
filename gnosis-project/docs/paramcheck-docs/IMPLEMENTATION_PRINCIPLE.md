# 参数动态校验组件实现原理

## 1. 系统架构

参数动态校验组件基于 Spring Boot 和 LiteFlow 2.11.3 构建，采用分层架构设计：

```
┌─────────────────────────────────────────────────────────┐
│                     控制层 (Controller)                 │
├─────────────────────────────────────────────────────────┤
│                     服务层 (Service)                   │
├─────────────────────────────────────────────────────────┤
│                     组件层 (Component)                 │
├─────────────────────────────────────────────────────────┤
│                     处理器 (Handler)                  │
├─────────────────────────────────────────────────────────┤
│                     仓储层 (Repository)                │
├─────────────────────────────────────────────────────────┤
│                     数据层 (Database)                  │
└─────────────────────────────────────────────────────────┘
```

## 2. 核心模块

### 2.1 动态校验服务 (DynamicValidationService)

- **功能**：统一入口，支持三种校验模式
- **路由策略**：
  - FLOW：通过 LiteFlow 引擎执行 EL 表达式编排
  - HANDLER：直接调用自定义处理器
  - HYBRID：先执行 FLOW，再执行 HANDLER
- **缓存机制**：对校验结果和流程配置进行缓存，提高性能

### 2.2 流程配置管理 (FlowConfigRepository)

- **功能**：从 openGauss 数据库读取和存储流程配置
- **表结构**：`gnosis_sample.sys_validation_flows`
- **核心字段**：
  - flow_id：流程唯一标识
  - mode_type：校验模式 (FLOW/HANDLER/HYBRID)
  - el_expression：LiteFlow EL 表达式
  - handler_code：自定义处理器编码
  - component_config：组件配置 (JSON)

### 2.3 处理器注册中心 (HandlerRegistry)

- **功能**：扫描并注册所有 `@ValidationHandler` 注解的处理器
- **实现**：启动时自动扫描，支持运行时动态注册

### 2.4 流程热加载服务 (FlowRefreshService)

- **功能**：从数据库加载流程配置并注册到 LiteFlow
- **特性**：
  - 启动时初始化
  - 定时轮询检测配置变更
  - 支持手动刷新

### 2.5 LiteFlow 组件

- **BasicRuleComponent**：基础规则校验
- **DbQueryComponent**：数据库查询校验
- **ParseParamComponent**：参数解析组件

## 3. 技术实现

### 3.1 缓存实现

- 使用 Spring 内置缓存机制
- 缓存流程配置和校验结果
- 提高系统性能，减少数据库访问

### 3.2 错误处理

- 自定义 `ValidationException` 异常类
- 支持错误码、错误消息和错误详情
- 预定义错误码：VALIDATION_ERROR、FLOW_ERROR、HANDLER_ERROR 等

### 3.3 配置管理 API

- RESTful API 接口
- 支持流程配置的 CRUD 操作
- 提供版本控制和刷新功能

### 3.4 LiteFlow 集成

- 支持从数据库动态加载流程
- 减少对配置文件的依赖
- 提供详细的配置指导

## 4. 数据流程

1. **请求接收**：客户端调用 `DynamicValidationService.execute()`
2. **流程加载**：从数据库加载流程配置（带缓存）
3. **模式选择**：根据流程配置选择校验模式
4. **校验执行**：
   - FLOW 模式：执行 LiteFlow 流程
   - HANDLER 模式：调用自定义处理器
   - HYBRID 模式：先执行 FLOW，再执行 HANDLER
5. **结果返回**：返回校验结果，包含错误信息（如有）
6. **日志记录**：记录校验失败的详细信息

## 5. 扩展机制

### 5.1 自定义处理器

- 实现 `IValidationHandler` 接口
- 添加 `@ValidationHandler` 注解
- 注册到处理器注册表

### 5.2 自定义 LiteFlow 组件

- 继承 `NodeComponent` 类
- 实现 `process()` 方法
- 在 EL 表达式中引用

## 6. 性能优化

- **缓存机制**：减少数据库访问
- **异步日志**：不阻塞主流程
- **批量处理**：支持批量校验
- **连接池**：优化数据库连接

## 7. 安全考虑

- **输入验证**：严格验证输入参数
- **SQL 注入防护**：使用参数化查询
- **权限控制**：配置管理 API 的权限控制
- **数据脱敏**：日志中的敏感信息脱敏

- **后端**：Spring Boot 2.7.x, Java 8

- **缓存**：Spring Cache
