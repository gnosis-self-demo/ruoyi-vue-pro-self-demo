# 统一消息通知组件开发手册

## 一、模块概述

`gnosis-notice-center` 是统一消息通知管理模块，为系统提供消息模板管理、消息发送、发送日志记录、站内信管理、频率限制、黑名单退订、定时发送、消息分组等功能。

### 1.1 功能特性

- **消息模板管理**：支持纯文本(TEXT)、富文本(RICH_TEXT)、HTML 格式模板，可配置变量占位符，支持模板版本管理
- **多通道发送**：短信、邮件、站内信、微信通知、钉钉通知（5个通道）
- **降级机制**：SMS/EMAIL/WECHAT/DINGTALK 配置未设置或网络异常时自动降级为日志模式
- **全链路日志**：记录每次发送的详细状态、请求参数、第三方响应
- **发送重试**：支持失败消息自动/手动重试（`retry_count` 递增）
- **异步发送**：`@Async` 注解实现异步发送，`async=true` 时后台执行
- **频率限制**：ConcurrentHashMap 滑动窗口计数，每分钟最大发送次数可配置
- **黑名单/退订**：发送前检查接收人是否退订，支持按通知类型或模板编码退订
- **定时发送**：支持指定未来时间发送，调度器每 60 秒扫描待发送任务
- **消息优先级**：0-普通、1-重要、2-紧急，影响展示排序和发送优先次序
- **消息分组**：通过 `group_id` 将关联消息归类，方便查询和管理
- **API 调用**：提供 `NoticeApi` 门面类供其他模块 Java 直调

## 五、其他模块调用方式

### 5.1 引入依赖

在调用模块的 `pom.xml` 中添加：

```xml
<dependency>
    <groupId>com.gnosis</groupId>
    <artifactId>gnosis-notice-center</artifactId>
    <version>${project.version}</version>
</dependency>
```

### 5.2 使用 NoticeApi

```java
@Service
public class YourService {

    @Autowired
    private NoticeApi noticeApi;

    // 方式1：使用模板发送（推荐）
    public void sendByTemplate() {
        NoticeSendRequest request = new NoticeSendRequest();
        request.setTemplateCode("ORDER_CREATE");
        request.setReceiver("13800138000");
        request.setParam("orderNo", "ORD20240101");
        request.setParam("amount", "100.00");
        request.setPriority(1);           // 重要消息
        request.setGroupId("order-group"); // 分组标记
        request.setAsync(true);            // 异步发送

        NoticeSendResponse response = noticeApi.send(NoticeChannelEnum.SMS, request, "userId001");
        if (response.getSuccess()) {
            System.out.println("发送成功，日志ID：" + response.getLogId());
        }
    }

    // 方式2：快速发送短信
    public void sendSmsQuick() {
```

## 八、降级机制

SMS、EMAIL、WECHAT、DINGTALK 四个通道均实现了降级机制：

- **触发条件**：配置未设置（如 `notice.sms.aliyun.accessKeyId` 为空）或网络异常
- **降级行为**：仅记录日志，不实际发送第三方消息，`NoticeSendResponse.success=true`
- **恢复方式**：补充配置后自动恢复真实发送，无需修改代码

## 十一、常见问题

### Q1: 如何新增消息通道？

1. 在 `NoticeChannelEnum` 中添加枚举值
2. 创建对应的 `XxxSender` 实现 `MessageSender` 接口，实现 `getNoticeType()` 返回通道编码
3. 新发送器会自动注册到 `senderMap`，无需手动注册（Spring 自动注入 `List<MessageSender>` 并构建 Map）

### Q2: 模板发送失败如何排查？

1. 检查 `sys_notice_log` 表的 `error_msg` 字段
2. 查看 `third_party_response` 第三方响应
3. 检查模板变量是否完整
4. 确认发送状态编码：0待发送、1发送中、2成功、3失败

### Q3: 如何配置第三方服务？

在 `application.properties` 中配置对应的服务参数，然后在 `XxxSender` 中读取配置。**配置缺失时自动降级为日志模式**，不会抛异常阻断流程。

### Q4: 发送是同步还是异步？

默认同步发送。如需异步，设置 `request.setAsync(true)`，系统将返回初始日志记录，实际发送在后台执行（通过 Spring `@Async` 注解实现）。

### Q5: 失败消息如何自动重试？

`NoticeRetryScheduler` 通过 `@Scheduled` 定时任务自动扫描 `send_status=3` 且 `retry_count < max_retry` 的记录，按 `notice.retry.interval` 配置的间隔进行重试，每次重试递增 `retry_count`。

### Q6: 频率限制如何工作？

`NoticeFrequencyService` 使用 ConcurrentHashMap 滑动窗口计数，60秒窗口内统计每个接收人的发送次数，超过5分钟的条目自动清理。最大每分钟发送次数由 `notice.frequency.max-per-minute` 配置控制。

### Q7: 如何退订通知？

通过 `NoticeBlacklistService` 或 REST API `/notice/blacklist/create` 添加退订记录。发送前会自动检查黑名单，退订人不会收到通知。支持按通知类型退订（`template_code` 为空）或按特定模板退订。
