# Java分批次SQL导出Excel需求说明书

## 1. 项目背景

某Java应用需要将数据库表中的大量数据（例如百万级）导出为Excel文件。传统一次性加载全部数据到内存会导致OOM（内存溢出），因此必须采用**分批次查询 + 流式写入Excel**的方式，严格控制内存峰值。

同时，应用需要支持**Excel数据导入回数据库**的能力，以及**导入/导出进度的外部监听**功能。

**目标数据库**：openGauss 3.0.0

---

## 2. 核心需求

1. **自动量级探测**：程序自动判断SQL查询的数据量级，自动计算分批大小，无需调用方手动指定。
2. **分批次读取**：根据自动计算的批次大小，使用SQL分页语法分批读取数据。
3. **流式生成Excel**：写入Excel时不能一次性构建全量工作簿，需使用支持流式的API（如SXSSFWorkbook）。
4. **动态分Sheet**：当数据量超过Excel单sheet行数上限（1,048,576行）时，自动创建多个Sheet。
5. **Excel再导入数据库**：支持将导出的Excel文件（含多Sheet）按规则导入回数据库，同样采用分批处理控制内存。
6. **进度回调**：支持外部监听导入/导出进度，便于UI展示或日志记录。
7. **内存可控**：内存峰值由程序自动控制在合理范围内（预估≤200MB）。
8. **通用性**：支持任意表结构（通过SQL或ResultSetMetaData动态获取列）。
9. **导出期间不禁用写操作**：不要求禁用数据库写入，不强制修改事务隔离级别。

---

## 3. 非功能性需求

| 项目 | 要求 |
|------|------|
| 内存峰值 | ≤ 200MB（通过自动分批控制） |
| 导出性能 | 导出10万行数据应在合理时间内完成（如<60秒，视网络/DB而定） |
| 导入性能 | 导入10万行数据应在合理时间内完成（如<120秒，视网络/DB而定） |
| 健壮性 | 中断操作能关闭资源，不留临时大对象 |
| 配置性 | 批次大小自动计算，无需手动配置 |
| COUNT超时保护 | COUNT查询超时（默认30秒）后采用保守批次大小并继续导出 |

## 4. 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 数据库 | openGauss 3.0.0 | 目标数据库版本 |
| JDBC | openGauss JDBC驱动 | 需正确配置游标参数 |
| Excel生成/读取 | Apache POI（SXSSFWorkbook / XSSFWorkbook） | 导出用SXSSF（低内存），导入用XSSF（流式读取） |
| 数据转换 | 手动映射（ResultSet ↔ Row） | 避免反射开销 |
| 进度回调 | 自定义ProgressListener接口 | 支持外部监听 |

### 4.1 openGauss 3.0.0 特殊配置

| 配置项 | 要求 | 说明 |
|--------|------|------|
| 分页语法 | `LIMIT {count} OFFSET {start}` | 标准SQL语法，不使用 `LIMIT offset, count` |
| 游标启用 | JDBC URL添加 `?prepareThreshold=0` | 使 `setFetchSize` 生效，控制客户端内存 |
| 事务要求 | 在事务块中执行查询 | 开启事务后才能使用服务端游标 |
| ResultSet类型 | `TYPE_FORWARD_ONLY` | 避免数据库全量缓存 |
| fetchSize | 设置为自动计算的batchSize | 控制每次从DB拉取的行数 |

## 6. 导出功能详细设计

### 6.1 数据量探测与自动分批

#### 6.1.1 数据量探测流程

```
开始导出
    │
    ├─1. 执行 COUNT 查询：SELECT COUNT(*) FROM (原SQL) AS t
    │      └─ 获取总记录数 totalRows
    │      └─ 超时阈值：30秒
    │
    ├─2. 根据 totalRows 自动计算 batchSize
    │
    ├─3. 根据 totalRows 计算所需Sheet数量
    │      └─ sheetsNeeded = ceil(totalRows / MAX_SHEET_ROWS)
    │      └─ MAX_SHEET_ROWS = 1,048,576（Excel上限）
    │
    ├─4. 记录日志：totalRows、batchSize、sheetsNeeded
    │
    └─5. 进入分批导出循环
```

#### 6.1.2 批次大小自动计算规则

| 数据量级 | 自动batchSize | 设计理由 |
|----------|---------------|----------|
| ≤ 5,000 | totalRows（全量） | 数据量小，一次性加载安全 |
| 5,001 ~ 100,000 | 5,000 | 兼顾内存与分页性能 |
| 100,001 ~ 500,000 | 10,000 | 大表减少分页次数 |
| 500,001 ~ 2,000,000 | 20,000 | 平衡内存与DB压力 |
| > 2,000,000 | 50,000 | 极大数据量，降低分页开销 |

### 6.2 动态分Sheet策略

#### 6.2.1 Sheet切换规则

```
单sheet最大行数 = 1,048,576（含表头）

导出过程：
  currentSheetRowCount = 0（含表头）
  currentSheetIndex = 0
  
  for each 数据行:
      if currentSheetRowCount == 0:
          创建新Sheet，写入表头
          currentSheetRowCount = 1
      else if currentSheetRowCount >= MAX_SHEET_ROWS:
          切换至下一个Sheet
          currentSheetIndex++
          创建新Sheet，写入表头
          currentSheetRowCount = 1
      else:
          写入数据行
          currentSheetRowCount++
```

#### 6.2.2 Sheet命名规则

| Sheet序号 | 名称示例（prefix="订单数据"） |
|-----------|------------------------------|
| 1 | 订单数据_1 |
| 2 | 订单数据_2 |
| 3 | 订单数据_3 |
| ... | ... |

> 如未指定prefix，默认使用 `Sheet1`、`Sheet2`、`Sheet3`...

### 6.3 导出流程图

```
开始
 │
 ├─1. 解析输入参数，获取totalRows
 │
 ├─2. 计算 batchSize 和 sheetsNeeded
 │
 ├─3. 初始化 SXSSFWorkbook
 │
 ├─4. 进度回调：onStart(totalRows, sheetsNeeded)
 │
 ├─5. 分页循环导出
 │      │
 │      ├─ sheet = 获取或创建当前Sheet
 │      │
 │      ├─ 执行分页SQL：LIMIT batchSize OFFSET offset
 │      │
 │      ├─ 遍历ResultSet，写入sheet
 │      │
 │      ├─ 每批次完成：进度回调 onBatchProgress(exportedRows, totalRows)
 │      │
 │      ├─ 如触发sheet上限：创建新sheet，进度回调 onSheetSwitch(sheetIndex)
 │      │
 │      └─ offset += batchSize
 │
 ├─6. 写入文件
 │
 ├─7. 关闭资源
 │
 ├─8. 进度回调：onComplete(totalRows, totalSheets, durationMs)
 │
 └─ 结束
```

## 7. 导入功能详细设计

### 7.1 导入流程

```
开始
 │
 ├─1. 打开Excel文件（使用XSSFWorkbook流式模式，避免全量加载）
 │
 ├─2. 遍历所有Sheet
 │
 ├─3. 对每个Sheet：
 │      ├─ 读取表头（第一行），获取列名列表
 │      ├─ 构建字段映射（Excel列 → 数据库字段）
 │      ├─ 生成 INSERT SQL（使用PreparedStatement批量插入）
 │      └─ 分批次读取数据行
 │
 ├─4. 进度回调：onStart(totalRows, totalSheets)
 │
 ├─5. 分批次导入循环（每个Sheet内部）
 │      │
 │      ├─ 读取batchSize行数据
 │      ├─ 转换为参数数组
 │      ├─ 执行批量插入（addBatch + executeBatch）
 │      ├─ 提交事务（每批次提交一次）
 │      ├─ 进度回调 onBatchProgress(importedRows, totalRows)
 │      └─ 释放当前批次内存
 │
 ├─6. 关闭资源
 │
 ├─7. 进度回调：onComplete(totalRows, totalSheets, durationMs)
 │
 └─ 结束
```

### 7.2 导入批次大小规则

| 场景 | 默认batchSize | 说明 |
|------|---------------|------|
| 自动模式 | 5,000 | 平衡内存与数据库事务开销 |
| 小文件（< 5000行） | 全量 | 一次性插入 |
| 大字段（TEXT/CLOB） | 1,000 | 降低内存压力 |
| 可配置 | 调用方指定 | 通过参数覆盖 |

### 7.3 列映射策略

| 映射方式 | 优先级 | 说明 |
|----------|--------|------|
| 显式映射（columnMapping参数） | 最高 | 调用方指定Excel列→数据库字段映射 |
| 名称自动匹配 | 中等 | Excel列名与数据库字段名大小写不敏感匹配 |
| 位置映射 | 最低 | 按Excel列顺序对应数据库字段顺序 |

**映射示例**：
```java
Map<String, String> mapping = new HashMap<>();
mapping.put("订单号", "order_no");
mapping.put("金额", "amount");
mapping.put("创建时间", "create_time");
// Excel列"备注"未映射则跳过
```

### 7.4 数据校验与异常处理

| 场景 | 处理策略 |
|------|----------|
| 类型不匹配 | 记录错误行号，跳过该行，继续导入（可配置是否中止） |
| 主键冲突 | 可选策略：跳过 / 更新 / 中止（默认跳过并记录日志） |
| 必填字段为空 | 跳过该行，记录错误 |
| 行数据格式错误 | 跳过该行，记录错误 |

## 8. 进度回调接口设计

### 8.1 ProgressListener 接口

```java
/**
 * 导入/导出进度监听器
 */
public interface ProgressListener {
    
    /**
     * 任务开始
     * @param totalRows   总行数（可能为-1表示未知）
     * @param totalSheets 总Sheet数
     */
    void onStart(long totalRows, int totalSheets);
    
    /**
     * 批次进度更新
     * @param processedRows 已处理行数
     * @param totalRows     总行数（可能为-1）
     * @param batchIndex    当前批次序号（从1开始）
     */
    void onProgress(long processedRows, long totalRows, int batchIndex);
    
    /**
     * Sheet切换（仅导出场景）
     * @param sheetName   新Sheet名称
     * @param sheetIndex  Sheet序号（从1开始）
     * @param rowsInSheet 该Sheet已写入行数
     */
    void onSheetSwitch(String sheetName, int sheetIndex, long rowsInSheet);
    
    /**
     * 任务完成
     * @param totalRows    总处理行数
     * @param totalSheets  总Sheet数
     * @param durationMs   总耗时（毫秒）
     */
    void onComplete(long totalRows, int totalSheets, long durationMs);
    
    /**
     * 发生错误（可选，是否继续由实现决定）
     * @param errorMsg  错误信息
     * @param rowNumber 错误行号（可能为-1）
     * @param cause     异常原因
     * @return true=继续执行，false=中止任务
     */
    boolean onError(String errorMsg, long rowNumber, Throwable cause);
}
```

### 8.2 默认实现示例

```java
/**
 * 日志进度监听器（仅输出日志）
 */
public class LoggingProgressListener implements ProgressListener {
    private static final Logger logger = LoggerFactory.getLogger(LoggingProgressListener.class);
    private long lastLogTime = 0;
    
    @Override
    public void onStart(long totalRows, int totalSheets) {
        logger.info("任务开始，总行数：{}，总Sheet数：{}", totalRows, totalSheets);
        lastLogTime = System.currentTimeMillis();
    }
    
    @Override
    public void onProgress(long processedRows, long totalRows, int batchIndex) {
        if (totalRows > 0 && processedRows % 10000 == 0) {
            double percent = (processedRows * 100.0) / totalRows;
            logger.info("进度：{} / {} 行 ({:.2f}%)，批次：{}", 
                       processedRows, totalRows, percent, batchIndex);
        }
    }
    
    @Override
    public void onSheetSwitch(String sheetName, int sheetIndex, long rowsInSheet) {
        logger.info("切换到Sheet：{}（第{}个Sheet），已写入 {} 行", 
                   sheetName, sheetIndex, rowsInSheet);
    }
    
    @Override
    public void onComplete(long totalRows, int totalSheets, long durationMs) {
        logger.info("任务完成，总行数：{}，总Sheet数：{}，耗时：{} ms", 
                   totalRows, totalSheets, durationMs);
    }
    
    @Override
    public boolean onError(String errorMsg, long rowNumber, Throwable cause) {
        logger.error("第 {} 行发生错误：{}", rowNumber, errorMsg, cause);
        return false; // 默认遇到错误中止
    }
}
```

## 10. 重要限制与注意事项

1. **SQL必须包含ORDER BY**：强烈建议SQL包含ORDER BY，防止分页时数据重复/遗漏。如未包含，程序输出警告但仍继续执行。

2. **Excel行数上限**：单sheet最多1,048,576行（含表头）。超出时自动创建新Sheet，已支持。

3. **导出期间允许写操作**：不要求禁用数据库写入，不强制修改事务隔离级别。

4. **临时文件**：SXSSFWorkbook会生成临时文件，确保磁盘空间充足（系统临时目录）。

5. **大数据类型**：CLOB/BLOB导出时需特殊处理（截断或转字符串），导入时需要流式读取。

6. **openGauss 3.0.0 配置**：
    - 分页使用 `LIMIT {count} OFFSET {start}` 语法
    - JDBC URL 添加 `?prepareThreshold=0`
    - 必须在事务中执行（`setAutoCommit(false)`）
    - ResultSet 使用 `TYPE_FORWARD_ONLY`

7. **导入事务**：每批次提交一次事务，避免长事务导致锁问题。单批次失败不影响已提交批次。

8. **进度回调线程安全**：ProgressListener实现需保证线程安全（回调可能来自不同线程）。

## 11. 异常处理要求

| 异常类型 | 导出处理策略 | 导入处理策略 |
|----------|--------------|--------------|
| COUNT查询超时 | 采用保守batchSize=10000，继续 | 不适用 |
| 分页查询超时 | 重试最多3次，失败则中止 | 不适用 |
| 数据行格式错误 | 记录并继续（通过listener回调） | 跳过该行，记录错误 |
| 主键冲突 | 不适用 | 跳过或更新（策略可配置） |
| 磁盘空间不足 | 停止，删除不完整文件 | 停止，回滚当前事务 |
| 连接断开 | 中止，保留已导出文件 | 中止，回滚当前批次 |
| OOM | 自动降低batchSize重试 | 自动降低batchSize重试 |

### 15.1 分页SQL示例（openGauss）

```sql
-- 原始SQL
SELECT id, order_no, amount, create_time 
FROM orders 
WHERE status = 'ACTIVE' 
ORDER BY id

-- COUNT SQL（自动生成）
SELECT COUNT(*) 
FROM (SELECT id, order_no, amount, create_time FROM orders WHERE status = 'ACTIVE') AS t

-- 分页查询SQL（第1页，batchSize=10000）
SELECT id, order_no, amount, create_time 
FROM orders 
WHERE status = 'ACTIVE' 
ORDER BY id 
LIMIT 10000 OFFSET 0
```

### 15.2 导入SQL示例

```sql
-- 单条插入
INSERT INTO orders (order_no, amount, create_time) VALUES (?, ?, ?)

-- 批量插入（JDBC addBatch）
PreparedStatement pstmt = connection.prepareStatement(insertSql);
for (Row row : batchRows) {
    pstmt.setString(1, row.get("order_no"));
    pstmt.setBigDecimal(2, row.get("amount"));
    pstmt.setTimestamp(3, row.get("create_time"));
    pstmt.addBatch();
}
pstmt.executeBatch();
connection.commit();
```
