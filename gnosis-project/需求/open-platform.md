# 需求背景描述
内外部联通组件，控制应用内外部数据集成和交互。

# 开放平台核心功能能力（极简配置终版）
**核心定位**：全量配置数据库化（表名统一前缀：`openplat_`），聚焦“来源精准识别+请求防重放+示例链接直达”，与现有API管理平台能力互补，零重复建设。

## 一、系统资产中枢
- **`openplat_system`**：存储对接系统核心信息（系统编码、名称、类型、负责人、状态）  
  ✅ 请求来源秒级识别（如“SRM供应商平台”“ERP采购模块”）

## 二、极简安全双核
- **来源认证**：`openplat_app_auth` 存储 `app_id`/`app_secret`/`system_id`，请求携带 `app_id` 即关联来源系统
- **防重放机制**：
    - 强制 `timestamp`（5分钟窗口）+ 唯一 `nonce`
    - `(app_id, nonce)` 写入 **`openplat_nonce_cache`**（自动过期）
    - HMAC-SHA256 签名校验（逻辑固化）  
      ✅ 无 IP 校验、无白名单、无复杂授权

## 三、协同配置矩阵（关键调整）
| 配置类型       | 数据表                | 核心作用                                  |  
|----------------|-----------------------|-----------------------------------------|  
| 系统资产       | `openplat_system`     | 对接系统全景管理                         |  
| 应用认证       | `openplat_app_auth`   | 来源系统身份绑定                         |  
| **API 配置**   | **`openplat_api_config`** | **路由/校验规则 + `example_url`（示例文档链接）** |  
| 文档元数据     | `openplat_api_doc`    | 接口说明、状态码定义                     |  
| Webhook 配置   | `openplat_webhook_config` | 事件订阅与回调策略                      |  
| 调用日志       | `openplat_access_log` | 全链路审计追溯                           |  
| 流量治理       | `openplat_rate_limit` | 限流熔断阈值                             |  
| 防重放缓存     | `openplat_nonce_cache`| nonce 临时存储（自动清理）               |  

## 四、示例链接直达（精准协同）
- **`openplat_api_config.example_url` 字段**：
    - 存储指向**现有API管理平台**中该接口的示例文档URL（含多场景请求/响应代码）
    - 开放平台仅提供跳转能力，示例内容维护由API管理平台统一负责
- **对接提效价值**：  
  ✅ 开发者点击链接直达标准示例（如“供应商创建订单”“合同状态回调”等场景代码）  
  ✅ 避免示例碎片化，确保上下游使用同一权威文档，降低沟通成本30%+
