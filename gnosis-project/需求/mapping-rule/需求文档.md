# 数据映射配置系统完整设计文档

## 一、需求设计说明

### 1.1 系统目标

构建一套灵活、可配置的数据映射转换系统，支持商务系统（采购、合同、供应商）的数据标准化和迁移融合，满足以下核心需求：

- **字段级映射**：支持简单字段直接匹配，包含类型转换、数据校验、必填检查
- **跨节点映射**：支持根节点与任意层级节点之间的双向字段映射
- **数组处理**：支持从数组中提取指定位置数据、条件筛选、值拼接等操作
- **字符串解析**：支持按分隔符拆分字符串为数组，并支持链式规则处理
- **批量数据处理**：支持List格式的批量数据转换，包含成功/失败分离
- **数据增强**：支持调用系统内方法、SQL查询、HTTP接口等多种数据源进行数据补充
- **校验机制**：内置完整的数据校验体系，确保数据质量

### 1.2 设计原则

- **配置驱动**：所有映射规则通过JSON配置文件定义，无需修改代码
- **灵活扩展**：支持自定义转换规则、校验规则、数据源类型
- **链式处理**：支持多级规则串联，实现复杂数据转换
- **容错降级**：提供缓存、重试、降级机制，确保系统稳定性
- **性能优化**：支持批量处理、缓存机制、并行处理，提升转换效率
- **批量处理**：支持List格式数据的批量转换和结果聚合

### 1.3 核心功能模块

```
数据映射配置系统
├── 字段直接映射模块
│   ├── 类型转换
│   ├── 数据校验
│   └── 必填检查
├── 跨节点映射模块
│   ├── 根节点→指定节点
│   ├── 指定节点→根节点
│   └── 节点间映射
├── 数组处理模块
│   ├── 按索引提取
│   ├── 条件筛选
│   ├── 值拼接
│   └── 格式化拼接
├── 字符串解析模块
│   ├── 分隔符拆分
│   ├── 链式规则处理
│   └── 数据补充
├── 批量处理模块
│   ├── List数据转换
│   ├── 成功/失败分离
│   └── 结果聚合
└── 数据源管理模块
    ├── 静态数据
    ├── 方法调用
    ├── SQL查询
    ├── HTTP接口
    └── Redis缓存
```

## 二、JSON配置字段详解

### 2.1 根配置结构

```json
{
  "configMetadata": {...},          // 配置元数据
  "apiConfig": {...},               // API配置
  "directMappings": [...],          // 场景1：字段直接映射
  "crossNodeMappings": [...],       // 场景2/3：跨节点映射
  "listExtractionMappings": [...],  // 场景4：数组提取
  "stringToListMappings": [...],    // 场景5：字符串转数组
  "forEachMappings": [...],         // 场景6：批量数据处理（方式1）
  "batchProcessing": {...},         // 场景6：批量数据处理（方式2）
  "arrayProcessingConfig": {...},   // 场景6：批量数据处理（方式3）
  "transformRules": {...},          // 转换规则定义
  "enrichmentMappings": {...},      // 数据增强映射
  "dataSources": {...},             // 数据源配置
  "validationEngine": {...}         // 校验引擎配置
}
```

| `batchCallEnabled` | boolean | 否 | 是否启用批量调用 | `true` |
| `batchSize` | integer | 否 | 批量大小 | `50` |

**sqlQuery特有字段：**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `dataSource` | string | 是 | 数据源名称 | `"dataSource"` |
| `sql` | string | 是 | SQL语句 | `"SELECT * FROM party_info WHERE party_name IN (:partyNames)"` |
| `parameters` | array | 否 | SQL参数 | `["partyNames"]` |

**httpCall特有字段：**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `url` | string | 是 | 接口地址 | `"http://api.example.com/party/info"` |
| `method` | string | 是 | HTTP方法 | `"POST"`, `"GET"` |
| `headers` | object | 否 | 请求头 | `{"Content-Type": "application/json"}` |
| `parameters` | array | 否 | 请求参数 | `["partyNames"]` |
| `timeout` | integer | 否 | 超时时间（毫秒） | `5000` |
| `retryTimes` | integer | 否 | 重试次数 | `3` |

**redis特有字段：**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `keyPattern` | string | 是 | Key模式（支持{fieldName}） | `"party:info:{partyName}"` |
| `keyField` | string | 是 | 关键字段 | `"partyName"` |
| `expireSeconds` | integer | 否 | 过期时间（秒） | `3600` |
| `fallbackDataSource` | string | 否 | 降级数据源 | `"methodCall"` |

#### 2.2.13 `validationEngine` - 校验引擎配置

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `stopOnFirstError` | boolean | 否 | 遇到第一个错误是否停止 | `false` |

## 四、配置使用总结

### 4.1 配置加载流程

```
1. 读取JSON配置文件
   ↓
2. 解析配置元数据和API配置
   ↓
3. 加载转换规则定义
   ↓
4. 加载数据源配置
   ↓
5. 初始化校验引擎
   ↓
6. 配置加载完成，等待数据转换
```

### 4.2 数据转换流程

```
1. 接收原始JSON数据
   ↓
2. 判断是否为批量处理（jsonRootPath是否指向List）
   ↓
3. 如果是批量处理：
   - 应用forEachMappings / batchProcessing / arrayProcessingConfig
   - 对每个item应用directMappings、crossNodeMappings等规则
   - 收集成功/失败结果
   ↓
4. 如果是单条处理：
   - 应用directMappings（字段直接映射）
   - 应用crossNodeMappings（跨节点映射）
   - 应用listExtractionMappings（数组提取）
   - 应用stringToListMappings（字符串转数组）
   ↓
5. 数据校验（如有配置）
   ↓
6. 返回转换后结果
```

### 4.3 配置最佳实践

1. **字段命名规范**：使用清晰、一致的字段命名
2. **必填字段校验**：对关键字段设置必填校验
3. **数据类型转换**：明确指定数据类型，避免隐式转换
4. **缓存策略**：对频繁调用的数据源启用缓存
5. **降级机制**：配置fallbackToStatic确保系统稳定性
6. **错误处理**：配置collectAllErrors收集所有错误信息
7. **性能优化**：合理设置maxItems限制数据量
8. **批量处理**：大批量数据使用arrayProcessingConfig方式，支持并行和结果聚合
9. **分页处理**：超大批量数据启用pagination配置

### 4.4 三种批量处理方式对比

| 配置方式 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| **forEachMappings** | 配置灵活，可针对不同数组配置不同规则 | 语法稍复杂 | 多个数组需要不同处理规则 |
| **batchProcessing** | 功能最完整，支持并行处理、结果聚合 | 配置较复杂 | 大批量数据处理，需要详细的结果统计 |
| **arrayProcessingConfig** | 配置最简洁，易于理解和维护 | 功能相对简单 | 简单的批量数据处理场景（推荐） |
