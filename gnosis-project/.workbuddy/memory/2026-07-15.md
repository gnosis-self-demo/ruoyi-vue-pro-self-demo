## gnosis-signature-plat 签章平台启动与验证

### 修复内容
1. **Jackson 版本冲突修复**: 父 pom.xml 的 dependencyManagement 中只覆盖了 `jackson-databind` 到 2.10.3，但 `jackson-core`/`jackson-annotations`/`jackson-datatype-jsr310` 仍是 Spring Boot 2.1.10 管理的 2.9.10 版本，导致 `NoClassDefFoundError: com/fasterxml/jackson/core/exc/InputCoercionException`。在父 pom 中补充了这3个依赖的版本管理，统一为 2.10.3。

### 启动方式
- **后端**: 由于 `spring-boot:run` 在多模块项目中会在父 pom 上执行失败，改用 `mvn dependency:build-classpath` 生成 classpath 文件，然后用 `java -cp "target/classes;$CP" com.gnosis.signature.SignaturePlatApplication` 直接启动
- **前端**: Vite 开发服务器 `vite --host`，端口 3008，代理 `/signature` → `http://localhost:8095`

### 验证结果
- **后端启动**: 成功 (27.9秒), Tomcat 端口 8095, openGauss 5个连接池连接, MyBatis-Plus 3.5.4, Swagger 63个API端点注册
- **前端启动**: 成功, Vite 端口 3008
- **API 测试**: 7个模块分页查询 + 供应商详情 全部返回 200
  - 供应商: total=3 (初始数据: 法大大/上上签/e签宝)
  - 流程: total=3 (初始数据: 顺序签/会签/并行签)
- **CRUD 测试**: 创建→查询→详情→批量启用→删除→验证删除 全流程通过
- **前端代理**: Vite 代理转发正常, 前端页面 HTML 200

## gnosis-notice-center 通知中心功能分析

### 分析结论
- 模块架构设计清晰（策略模式Sender + 门面模式NoticeApi），但实现处于半成品状态
- **核心缺失**: SMS/EMAIL/WECHAT三个发送通道为桩实现（仅打印日志+模拟成功），自动重试定时任务未实现，异步发送未落地
- **规范违规**: sys_notice_log和sys_notice_inbox缺少update_user_id/update_time字段；日志和站内信页面缺少导入导出
- **集成空白**: 与lifecycle/规则引擎组件的对接尚未启动
- **其他问题**: userId硬编码为admin；快速发送未创建日志；Redis/Caffeine引入但未使用；无单元测试

- `gnosis-notice-center功能分析报告.md` — 完整的需求对比、问题清单、拓展建议
